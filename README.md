# set-cover

带成本的集合覆盖（贪心 + 精确解），只用 Python 标准库。

```
python3 -m setcover.cli --sets 'a=2:1,2;b=2:3,4;c=5:1,2,3,4' --universe 1,2,3,4
python3 -m setcover.cli --sets 'a=2:1,2;b=2:3,4' --universe 1,2,3,4 --exact
python3 -m unittest discover -s tests -v
```

## 口径（README 为准）

- **贪心按「成本 ÷ 新增覆盖元素数」挑，不是按覆盖元素个数**：
  `--sets 'a=2:1,2;b=2:3,4;c=5:1,2,3,4' --universe 1,2,3,4` 按口径是 `cost=4`、`sets=a,b`，
  现在因为只看元素个数而挑了 c，给 `cost=5`、`sets=c`。
- **精确解**：`--exact` 在集合数 ≤ 16 时给最小成本覆盖（要能剪枝，不许把 2^16 个子集全枚举一遍）；
  现在 `--exact` 直接报「精确解还没实现」。
- **覆盖不全要报错**：`--sets 'a=1:1' --universe 1,2` 现在静默给 `cost=1`，
  按口径要报错并按字典序列出未覆盖元素（这里是 `2`）。
- 输入：`--sets` 用 `;` 分隔，每项是 `名字=成本:元素,元素`；元素按字面比较；同一次输入里元素重复要忽略；
  成本必须是正整数；集合名重复、名字为空、缺 `=`、缺 `:`、成本非数字都要报错并指出是第几个 `--set` 项。
- 不变量：选出的集合必须覆盖全集；`cost` 必须等于所选集合成本之和；同一输入重复运行结果相同，
  成本相同时按集合名字典序取最小的一组。
- 规模：5000 个集合、10 万个元素时，每轮贪心不许重扫全部集合（用堆或索引），1 秒内给结果。
- 对照自证：集合数 ≤ 16 的随机输入，`--exact` 的结果必须与「枚举所有子集取最小」的穷举逐例一致。

## 现在的行为

- `greedy` 每轮只比 `len(集合 ∩ 未覆盖)`，成本完全不看：上面的样例给 `cost=5`（应 4）。
- `exact_cover` 还没实现，`--exact` 直接报错退出。
- 覆盖不全时不报错：剩下的元素被丢掉，照样打印 `cost=` 与 `sets=`。
- `parse_sets` 用 `int()` 直接转成本，`a=x:1` 抛的是原始 `ValueError`；集合名重复也不检查。

## 计划新增的能力

```
--sets 集合表        分号分隔的 名字=成本:元素,元素
--universe 全集      默认取所有元素的并集
--exact              求最小成本覆盖
```

## 输出

```
cost=4
sets=a,b
```
